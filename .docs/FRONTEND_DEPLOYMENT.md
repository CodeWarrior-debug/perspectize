# Frontend deployment (Sevalla / Cloudflare edge)

Moved from `frontend/CLAUDE.md`. Read before touching `static/_headers`, `static/_redirects`, `app.html`'s `#stale-chunk-recovery`, `lib/utils/versionWatch.ts`, `kit.version`, `static/manifest.webmanifest`, or when debugging a deployed-only load failure.

**`static/_headers` and `static/_redirects` are load-bearing.** adapter-static builds a pure static site with content-hashed `_app/immutable/*` chunks; Sevalla serves it behind Cloudflare. Two gotchas compound if either file is missing or edited carelessly:

- **`_redirects`** (`/* /index.html 200`) makes client-side routing survive a hard refresh, but _any_ missing path, including a previous deploy's deleted hashed chunk, then resolves to a 200 `text/html` response instead of a 404.
- **`_headers`** caps `index.html`/the SPA fallback at `Cache-Control: ... s-maxage=0` (always revalidate), while `_app/immutable/*` keeps a long, immutable cache. Without `s-maxage=0`, Cloudflare's edge can serve a deploy-old `index.html` for up to 30 days; it references the _previous_ deploy's chunk filenames, and the missing-chunk request hits the `_redirects` catch-all and returns `text/html` instead of JS.

Symptom: `Failed to load module script: Expected a JavaScript-or-Wasm module script but the server responded with a MIME type of "text/html"` on the deployed site (not reproducible locally: no CDN layer). **This is a caching/hosting-config issue, not a service worker issue.** Check it first (`curl -I` the failing chunk URL, or a live `fetch()` from the deployed page) before assuming a service worker cause; there is no service worker in this app. After touching either file: `pnpm run build`, then confirm `build/_headers` and `build/_redirects` exist.

**`_headers` block overlap MERGES `Cache-Control`; it does not override.** Cloudflare Pages/Sevalla applies every `_headers` block whose path matches. If two match (e.g. `/_app/immutable/*` and a `/*` catch-all, for any existing chunk), their `Cache-Control` values are comma-concatenated, not resolved by specificity (confirmed live). Only one splat (`*`) per rule and no exclusion syntax, so a catch-all can't exclude a narrower pattern. Make the catch-all's value safe to merge: include a bare `no-cache` token (forces revalidation whatever else is concatenated) rather than relying on directive order or specificity.

**Fresh cache headers don't cover a page that is already running.** Any tab that outlives a deploy (phone tab or home-screen app resumed from memory, pinned or session-restored desktop tab, bfcache restore) is still on the old build. Its next lazy import asks for a deleted chunk, gets the `_redirects` HTML, and the page goes blank until a manual refresh. `_headers` can't fix this, and `_redirects` can't answer 404 for `/_app/*` (Cloudflare-style `_redirects` supports only 200/3xx). Recovery is client-side in three layers. Keep all three:

- `app.html` `#stale-chunk-recovery` (inline, above SvelteKit's bootstrap): on `vite:preloadError`, a chunk-load `unhandledrejection`, or a failed `/_app/` `<script>`/`<link>`, it reloads once. A 30s `sessionStorage` guard stops reload loops by showing a "Reload" banner instead. It never auto-reloads when offline or when storage is unavailable.
- `lib/utils/versionWatch.ts` (mounted in `+layout.svelte`): checks `_app/version.json` when the tab becomes visible, is restored from bfcache, or the window regains focus (at most once a minute; a desktop window left on screen never fires `visibilitychange`), and reloads if a newer build exists. It skips the reload while an input or contenteditable has focus.
- `version.pollInterval` (the `withPwa`/`sveltekit()` options in `vite.config.ts`) plus the layout's `beforeNavigate`: once `updated.current` is true, the next in-app navigation becomes a full page load.

**There is no service worker and no `@vite-pwa/sveltekit` plugin.** The web manifest is a static file (`static/manifest.webmanifest`, linked from `app.html`), which is all Add to Home Screen needs. Nothing is precached, so a deploy cannot delete the chunks of a tab still running the old build. Re-adding a native shell or a service worker is deferred until a mobile release is scheduled (see FEATURE_BACKLOG.md). Before adding a precaching worker, remember that it would bring back the version-skew problem above.
