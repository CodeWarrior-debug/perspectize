# Mobile Views Critique — 2026-04-10

> Generated by `/critique mobile views`. Review against the design brief in `.impeccable.md`.
> Score: **20/40** — needs meaningful work. Target range for shipped products: 28–34.
> Scope: mobile viewports (xs <445px, sm 445–639px). Desktop issues are out of scope.

---

## TL;DR

The **engineering** is considerably better than the **mobile design**. The architecture honors the brief (dual Geist/Charter fonts, AG Grid tier system, FormPopover mobile→Dialog swap, pagination over infinite scroll, rating tokens in `app.css`). But on a 375×812 phone the user sees a generic admin dashboard for a YouTube database, not a calm editorial reading room.

**The single biggest opportunity:** the mobile home is ~100% chrome and ~0% perspective content. Kill the wrapping card, hide the "Activity" H1 on xs/sm, let the list bleed edge-to-edge, and rewrite every system string in the project's brief voice. Those two moves alone would jump the heuristic score ~4–6 points and eliminate the "admin panel" first-impression.

**Open question not yet answered:** should the mobile home _be_ the AG Grid at all, or should mobile become a card-list? Deferred for a later session — see Question 2 below.

## Anti-Patterns Verdict

### What's absent (good)

- No gradient text
- No `border-left` accent stripes
- No glassmorphism
- No infinite scroll
- No avatar feeds / social chrome
- No red YouTube-clone accents

### What's creeping in (bad)

- **Card-in-card nesting.** `+page.svelte:52` wraps the AG Grid in `border rounded-lg shadow-sm`, and `ActivityTable.svelte:652–683` puts the FilterChips band _inside_ that card. The brief explicitly bans this.
- **Hardcoded saturation colors outside tokens.** `PerspectivePopover.svelte:227–247` uses `bg-green-500` / `bg-red-500` / `border-green-500` / `border-red-500`. These bypass `--color-rating-positive` / `--color-rating-negative` (defined `app.css:82–84`) and will render as neon artifacts in every future curated theme.
- **Bland system strings.** "Activity" / "Recently updated content" / "No content yet" / "Failed to load content. Please try again." / "Loading…" — every one is LLM-default corporate. The brief's single biggest voice lever is un-pulled.
- **Hardcoded AG Grid hexes.** `ActivityTable.svelte:242–257` sets `headerBackgroundColor: '#1a365d'` and other raw hexes in `themeQuartz.withParams()`, bypassing theme tokens.

### Deterministic scan (npx impeccable)

One finding:

- **`pure-black-white`** in `frontend/src/lib/components/shadcn/dialog/dialog-overlay.svelte:12` — uses `bg-black` for the dialog scrim. Shadcn-svelte default. Replace with `bg-foreground/80` or a tinted `oklch(12% 0.01 250)`. Note: `PerspectivePopover.svelte:174` has the _opposite_ failure — `overlay=bg-transparent`. The project is making inconsistent scrim choices.

## What's Working

1. **AG Grid responsive tier system** — `ActivityTable.svelte:567–629`. Four tiers, explicit column-reveal order, correctly uses `matchMedia` with `isMobile: true` requirement. Genuinely thoughtful engineering and the right bone structure for any future "calm mobile" work.

2. **`FormPopover`'s mobile→Dialog auto-swap** — `FormPopover.svelte:50–88`. Correctly detects `(max-width: 767px)` and swaps popover for dialog. Add-Video and Create-User benefit automatically. This is the right pattern — it just needs to become the project's _only_ dialog pattern. PerspectivePopover currently rolls its own and gets it wrong.

3. **`RatingInput`'s numerals-as-jewelry execution** — `RatingInput.svelte:138–216`. Tabular monospace numerals, click-to-set progress bar, value-driven color via rating tokens (not hex), clear button on interaction. At the component level this is the brief's "numerals as jewelry" promise being kept.

4. **Charter is actually loaded and used in body cells** — `app.css:152–154`. Not flattened to Geist. The dual-font signature survives.

## Priority Issues

### [P1] Mobile home has no hero and no voice — it's a table in a card

**Files:** `+page.svelte:29–56`, `Header.svelte:6`, `ActivityTable.svelte:652`.

**Why it matters:** The brief says "Content is sovereign" and "chrome recedes." On a 375×812 phone the user sees 5 horizontal chrome bands (header, page-header, filter band, grid header, pagination footer) over ~2–3 rows of data. That is the opposite of the intent, and it's the #1 reason the first impression reads as generic SaaS.

**Fix:**

- Kill the `border rounded-lg shadow-sm` card wrapper on mobile (`+page.svelte:52`). Let the list bleed edge-to-edge.
- Reduce page-header padding on xs/sm (`px-4 md:px-6` → `px-0 sm:px-6`, or hide entirely on xs).
- Replace the "Activity" H1 on mobile with a Charter editorial moment — a teaser of the most recently saved perspective, or a single literary line. Or drop the H1 entirely on xs.
- Decide (see Question 2 below): mobile = list vs mobile = grid-with-fixes.

**Suggested commands:** `/arrange` for layout restructure, then `/distill` to rip out chrome that isn't earning its keep.

### [P1] Touch targets below 44×44 across rating + filter + pagination controls

**Files:**

- `RatingInput.svelte:147–199` — stepper chevrons `size-3.5`, clear-X `size-3` absolute `-right-5`
- `FilterChips.svelte:147–153` — X inside `p-0.5`
- `ActivityTable.svelte:714–730` — pagination `<`/`>` at `px-3 py-1 text-sm`

**Why it matters:** WCAG 2.5.5 and Apple HIG both want 44pt minimum. The `RatingInput` clear-X positioned `-right-5` is especially risky at 320px viewports — inside a 2-col grid with `gap-4` in a `max-w-sm` dialog with `px-6+px-2` padding, it can clip offscreen entirely.

**Fix:**

- Stepper buttons: `p-2 min-w-[44px] min-h-[44px]`.
- Clear-X: move inline next to the number, not absolutely positioned.
- Pagination: replace `<`/`>` with full "Prev"/"Next" labels, `min-h-[44px]`.
- `FilterChips` X: expand hit area to ≥32px without growing the visible X glyph.

**Suggested command:** `/harden` for the touch-target pass.

### [P1] PerspectivePopover hover-only tooltip + hardcoded saturation colors

**Files:**

- `PerspectivePopover.svelte:183–197` — `opacity-0 group-hover:opacity-100` info tooltip
- `PerspectivePopover.svelte:227–247` — `bg-green-500` / `bg-red-500` / `border-green-500` / `border-red-500`
- `PerspectivePopover.svelte:174` — `overlay=bg-transparent`

**Why it matters:**

- (a) The help tooltip explaining "Add as much or as little as you like" is unreachable on touch. Mobile users will never see it. That's the Help-and-Documentation 1/4 score in one widget.
- (b) The saturated greens/reds bypass `--color-rating-positive` / `--color-rating-negative`. Every future curated theme (Archive, Garden, Midnight, Terminal) will render them as neon artifacts.
- (c) The transparent overlay makes the dialog float over the grid with no scrim — reads as a floating panel, not a modal focus moment.

**Fix:**

- Replace group-hover tooltip with a small always-visible Charter-italic subtitle beneath the perspective name.
- Replace `bg-green-500` / `bg-red-500` with `bg-[var(--color-rating-positive)]` / `bg-[var(--color-rating-negative)]` or their Tailwind-token equivalents.
- Give the dialog a real scrim (`bg-foreground/80` or tinted variant).

**Suggested commands:** `/normalize` to pull colors back onto tokens, then `/clarify` for the tooltip rewrite.

### [P2] Every system string is LLM-default corporate — the biggest voice lever is un-pulled

**Files:** `ActivityTable.svelte:526, 562–563, 660` · `+page.svelte:35` · `+layout.svelte:45` · `AddVideoDialog.svelte:74` · most toasts.

**Why it matters:** The brief says verbatim: "Empty states, 404s, loading states, and system messages are the places to be playful… Humor and personality appear in copy, in microcopy, in empty states, in 404s, in the way a number is set." Every one of these strings currently reads like a generic admin template. Zero editorial voice, zero cleverness, zero New-Yorker-caption-writer energy.

**Fix:** Rewrite every system string in-voice. Illustrative directions (not final copy):

| Location      | Before                                      | Toward                                                                        |
| ------------- | ------------------------------------------- | ----------------------------------------------------------------------------- |
| Empty state   | "No content yet"                            | "Nothing in the archive yet. Paste a video to begin."                         |
| No results    | "No results match your filters"             | "Nothing here matches. Loosen the filters, or just scroll."                   |
| Load error    | "Failed to load content. Please try again." | "The archive is quiet. Try again in a moment."                                |
| Page subtitle | "Recently updated content"                  | Charter-italic literary phrase — "What you've been thinking about" or similar |
| Loading       | "Loading..."                                | "Gathering your perspectives…" or a Charter-italic ellipsis                   |

Don't commit these verbatim — the actual copy needs the voice tuned intentionally. But the pattern is clear: every string gets written, no string is default.

**Suggested command:** `/clarify` with the explicit mandate to rewrite system strings in the `.impeccable.md` voice.

## Questions to Consider

1. **What if the mobile home _is_ a single perspective, not a grid?** The brief says "the perspective is the hero object, the table is just a way to find it." On mobile, why is the table the first thing the user sees? A Charter-set cover card with today's most recent perspective, followed by a light recent-list, would honor the brief in a way the current layout can't.

2. **Is AG Grid even the right tool on mobile?** At xs/sm you've amputated it to 3 columns. That's not a grid, it's a list with extra steps. A native Svelte card-list (same URL state, sort, filter) would feel more like a reading room — and unlock swipe affordances, tap-to-expand, and proper touch targets by default. **Open — deferred for a later session.**

3. **Where is the theme picker?** The brief calls it first-class. Currently: not started. If the first thing a mobile user can customize is their reading room, that's a peak-end moment waiting to happen. Could this be where you start reclaiming the "beautiful, clever" axis?

4. **What does "effortless to input" actually mean on a phone?** Right now adding a video is: tap Add → leave to YouTube → copy → come back → paste → submit. Should the mobile version be a share-target intent (Android share sheet + iOS Shortcut), so YouTube → Share → Perspectize is one tap with auto-populated URL?

5. **Would removing the H1 "Activity" break anything?** The word is content-free and corporate. If you deleted it on mobile, what would you put in its place? If the answer is "nothing, just the list," the chrome was never earning its keep.
