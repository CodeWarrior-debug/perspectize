# Painting content type — design proposal

**Status:** Proposal (not started). **Date:** 2026-09-26.
**Generated with:** `tools/content-type-designer`, seeded from its new `painting` profile (`src/catalog.ts`).
Everything from "Content type spec: Painting" down is the tool's verbatim `buildSpec` + `buildMatrix` output.
The only hand-written parts are this header and the review notes.

## Goal

Users can add a **fine-art painting** (not house, decorative or protective painting) and write a perspective on it. They see a thumbnail, click through to the painting's museum page, and see its metadata: artist, date, medium and collection.

## Source decision (research 2026-09-26, APIs called live)

| API | Verdict |
|---|---|
| **The Met Collection API** | **Primary.** No key, CC0 images, one request per painting, 80 req/s. Returns thumbnail, `objectURL`, artist/date/medium/dimensions, tags with Wikidata IDs, and the painting's own Wikidata QID. |
| Wikidata / Commons | **Phase 2.** About 408k paintings with images (`P31 = Q3305213` with `P18`). It covers paintings the Met doesn't hold, and the Met's QID shares the same dedup key. |
| Harvard Art Museums | Rejected. Non-commercial use only, 2,500 requests/day, caching capped at two weeks. |
| Rijksmuseum | Rejected as primary. The old API returns `410 Gone`. The new Linked Art API needs no key, but getting an image takes 3 hops. |
| Europeana | Rejected as primary. Needs a key, and rights and metadata quality vary per item. |
| Art Institute of Chicago | Rejected as primary. 60 requests/minute, about 2k public-domain paintings, and its IIIF server returned 403 to server-side fetches from a cloud IP. |
| Google Arts & Culture | No public API. |

## Findings from real Met records that shaped the bindings

- **Gate on `objectName == "Painting"`, not `classification`.** *Washington Crossing the Delaware* (Met 11417, The American Wing) has an empty `classification`.
- **Some paintings have no open-access image.** Monet's *Bridge over a Pond of Water Lilies* (Met 437127) has `isPublicDomain: false` and a blank `primaryImageSmall`. Fall back to its Wikidata QID → `P18` → Wikimedia Commons, with attribution.
- **Dates are approximate.** Vermeer's `objectDate` is "ca. 1662" while `objectBeginDate` is 1657. Display the string and sort by the integer.
- **Dimensions are not Length.** Size is kept in JSONB for the details modal. Binding it to Length would mix physical size with durations, pages and words.

## Review notes on the tool output

- **§6 MUST FIX (Length, Views):** these come from the YouTube side of the Painting + YouTube preview. Under the `majority` rule, any YouTube-only required column is hidden once a second type is selected. Painting does better than Bible passage here (2 errors vs 4) because it shares Creator and Date with YouTube. The fix belongs to the grid, not to this type: pin those columns whenever YouTube is in the filter.
- **§3 "Migration needed: creator, rating":** this is the tool's generic promoted-column rule for shared columns. It isn't specific to paintings and should be decided once, across all types.

## 8. Testing approach

Go: table-driven tests for the Met URL parser (valid object URL, trailing slash, query string, non-numeric id, non-Met host) and for the gate (objectName "Painting" accepted with blank classification — Met 11417; "Print"/"Drawing" rejected). httptest fixture for the Met client, including a record with blank primaryImageSmall (437127) to exercise the Commons fallback. Frontend: Item cell renders object-fit: contain thumbnail, palette icon when image_url is null, and Painted sorts by objectBeginDate not the display string.

## 9. Conventions to ignore for this work only

Dimensions (e.g. "28 13/16 × 36 3/4 in. (73.2 × 93.4 cm)") and creditLine are stored in response JSONB and shown only in the details modal — deliberately NOT bound to Length, which would mix physical size with durations/pages/words. The Met API has no description text, so Description stays unbound until the Wikidata/Wikipedia phase.
