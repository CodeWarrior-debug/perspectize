# Requirements: Perspectize v1.2 Jeeves AI Assistant

**Defined:** 2026-09-26
**Runs in parallel with:** v1.1 Platform Expansion (`.planning/REQUIREMENTS.md` / `v1.1-REQUIREMENTS.md` untouched)
**Core Value:** Users can easily submit their perspective on content and browse others' perspectives in a way that keeps them in control. Jeeves helps without taking control.
**Research:** `.planning/v1.2-research/SUMMARY.md` · **Locked decisions:** `ai-tooling/CLAUDE.md`

**Progressive planning:** Phase 25 requirements are firm. Phases 26–28 are **provisional**: re-scoped at each phase transition from what the previous phase learned (eval results, token costs, guide size).

---

## v1.2 Requirements

### App Guide (GUIDE): Phase 25
- [ ] **GUIDE-01**: Jeeves has a task-oriented app guide covering every user-facing area of the current frontend, with stable entry IDs
- [ ] **GUIDE-02**: Every guide entry cites source files and passes an independent verifier's check against the code (closed loop, max 3 rounds, then escalate)
- [ ] **GUIDE-03**: Guide format and source paths are linted in CI, so a broken or stale guide fails the build
- [ ] **GUIDE-04**: Each area has 3 or more eval seed questions, including at least one "unsupported feature" trap

### AI Core (CORE): Phase 25
- [ ] **CORE-01**: `ai-tooling` defines provider-neutral message, tool, stream-event (start, text delta, tool activity, done, error) and usage types; no SDK type appears outside an adapter
- [ ] **CORE-02**: An Anthropic adapter (official Go SDK) streams responses and translates tool calls, stop reasons (including refusal) and usage to neutral types
- [ ] **CORE-03**: A hand-written agent loop runs tool rounds with a round cap, tool-result size limits, parallel tool calls and context cancellation
- [ ] **CORE-04**: A tool registry validates model-supplied tool input against each tool's JSON Schema before running the handler
- [ ] **CORE-05**: The model, max tokens and round cap come from configuration, not code

### Jeeves Tools (TOOLS): Phase 25
- [ ] **TOOLS-01**: Jeeves can answer how-to questions from the guide (current page's section in the prompt, plus a `read_guide` tool for the rest)
- [ ] **TOOLS-02**: Jeeves can read the user's own perspectives and others' *public* perspectives on a piece of content (read-only)
- [ ] **TOOLS-03**: Every `PerspectizeData` call takes an explicit viewer; one shared contract test proves no implementation returns another user's private perspective
- [ ] **TOOLS-04**: Tool results wrap user-generated text as untrusted data (prompt-injection hygiene)

### Dev CLI (CLI): Phase 25
- [ ] **CLI-01**: Owner can run `botler tools list` and `botler tools call <name> --input` against the GraphQL API without the model
- [ ] **CLI-02**: Owner can run `botler chat` for a full streamed agent loop in the terminal, with tool calls visible
- [ ] **CLI-03**: `botler` authenticates with a mechanism that can't be active in production (decision pending: dev-only header vs long-lived Clerk token)

### Evals (EVAL): Phase 25
- [ ] **EVAL-01**: Owner can run `botler eval --model <id>` against fixture data (never the shared dev DB)
- [ ] **EVAL-02**: Deterministic checks cover tool selection, tool arguments, guide-ID grounding, unsupported-feature traps, privacy and injection resistance
- [ ] **EVAL-03**: Each case runs N times (default 3); the report shows pass rate, tokens (including tool-definition tokens) and latency per model × prompt version
- [ ] **EVAL-04**: A Claude baseline is recorded, and "following nicely" is defined as a pass-rate threshold

### Bridge (BRIDGE): Phase 26 (provisional)
- [ ] **BRIDGE-01**: Backend builds with `ai-tooling` imported: Docker context at repo root, root `.dockerignore` excluding secrets, verified by a Sevalla deploy (its own PR)
- [ ] **BRIDGE-02**: The perspective visibility check lives in `PerspectiveService` (not only the resolver), covered by the TOOLS-03 contract test against the in-process implementation

### In-App Jeeves (INAPP): Phase 27 (provisional)
- [ ] **INAPP-01**: User can open a Jeeves sidebar (sheet on mobile) on demand; it never opens or nudges on its own
- [ ] **INAPP-02**: User sees responses stream in and can press Stop, which cancels the upstream model call
- [ ] **INAPP-03**: User sees which guide entries an answer came from, and an honest "Perspectize doesn't do that" for unsupported features
- [ ] **INAPP-04**: Jeeves gets only the current page's tools (server-side mapping from a page enum)
- [ ] **INAPP-05**: User can rename the assistant (default "Jeevesbot") in Settings; the name is validated and treated as a label only
- [ ] **INAPP-06**: User can accept or dismiss a proposed change on a confirm-to-apply card showing the before and after; nothing is written without Apply
- [ ] **INAPP-07**: Assistant output renders through a dedicated renderer that never outputs images, iframes, forms or styles
- [ ] **INAPP-08**: User sees clear limit messages; per-user rate and token budgets are enforced in the service layer (subscriptions bypass the HTTP limiter)
- [ ] **INAPP-09**: Every model call logs usage (user, provider, model, tokens, cost units), and the log survives Stop
- [ ] **INAPP-10**: Screen readers get "responding" and completed-answer announcements, not token-by-token updates

### Providers (PROV): Phase 28 (provisional)
- [ ] **PROV-01**: An OpenAI-compatible adapter (OpenRouter) passes the same agent-loop and tool tests as the Anthropic adapter
- [ ] **PROV-02**: A model registry records provider, model ID, tool support, context size and cost; models without reliable tool support can't be selected for tool use
- [ ] **PROV-03**: The cross-model eval matrix decides which models are offered; the pivot happens only once the EVAL-04 threshold is met

## Future Requirements (deferred)

- Credits ledger, token purchases (Stripe), BYOK key vault
- Remote MCP server + OAuth (small intent-level core + `find_tools`), serving external AI clients and a future Chrome extension
- Chrome extension "Add this page" button (needs a generic URL/article content type)
- Autonomous low-risk actions (ladder rung 4)
- Persisted conversation history across sessions
- Guide drift check in CI (flag entries whose source files changed)
- Model-graded quality evals (rubric judge)

## Out of Scope

| Item | Reason |
|---|---|
| Proactive nudges / unprompted suggestions | Violates the calm, user-in-control core value |
| Silent writes | Everything that writes goes through confirm-to-apply |
| Ghost-writing perspectives by default | Jeeves refines by asking questions; the user's voice stays theirs |
| Voice input | Deferred per v1.1 research |
| gRPC | The interface leaves room; there's no need yet |
