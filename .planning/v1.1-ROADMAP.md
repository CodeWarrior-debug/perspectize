# Roadmap: Perspectize v1.1 Platform Expansion

## Overview

This roadmap transforms Perspectize from a YouTube-only MVP into a robust content platform with authentication, content categorization, discovery features, and power-user tools. Building on the v1.0 foundation (38 plans executed), v1.1 adds 6 phases focusing on infrastructure migration, database optimization, security, and user experience.

## Phases

**Phase Numbering:** Continues from v1.0 (ended at Phase 10). v1.1 starts at Phase 11.
Decimal phases (10.5) are urgent insertions (marked with INSERTED) and appear between their
surrounding integers in numeric order.

- [ ] **Phase 10.5: Neon Postgres Migration & Infra Tuning** — Move production DB from Sevalla to Neon; pooling/indexing/extension/storage tuning with before/after benchmarks (INSERTED)
- [ ] **Phase 11: Database Optimization** — JSONB trimming, column extraction, index optimization, server-side sort/filter
- [ ] **Phase 12: Authentication & Security** — JWT auth, Argon2 passwords, protected routes, cache scoping
- [ ] **Phase 13: Content Categories** — Google NL taxonomy, Claude auto-suggestion, category picker UI
- [ ] **Phase 14: AG Grid Power Features** — Toolbar, filter management, column visibility, state persistence
- [ ] **Phase 15: Discover Page** — YouTube search, category browsing, one-click add

## Phase Details

### Phase 10.5: Neon Postgres Migration & Infra Tuning (INSERTED)
**Goal**: Move the production PostgreSQL database from Sevalla to Neon with no data loss, and
land infra-level performance tuning (connection pooling, indexing-for-Neon, extensions,
storage-tuning assumptions) with documented before/after benchmarks. Distinct from Phase 11's
schema-level optimization work.
**Depends on**: v1.0 complete
**Spec**: `docs/superpowers/specs/2026-09-03-neon-postgres-migration-design.md`
**Plans** (superpowers, not GSD-native — see `docs/superpowers/plans/`):
- `docs/superpowers/plans/2026-09-03-neon-postgres-migration-plan.md`
- `docs/superpowers/plans/2026-09-03-neon-performance-tuning-plan.md`
**Success Criteria** (what must be TRUE):
  1. Production traffic is served entirely from Neon; Sevalla database is decommissioned
  2. All existing backend tests pass against Neon
  3. No data loss versus the pre-cutover Sevalla state (row-count and spot-check parity)
  4. Documented before/after benchmark numbers exist for the app's hot queries (Sevalla
     baseline vs tuned Neon)
**Estimated effort**: 1-2 weeks
**Risk**: MEDIUM — production data migration; mitigated by brief-downtime cutover (no logical
replication needed) and Neon's copy-on-write branching for zero-risk tuning iteration

### Phase 11: Database Optimization
**Goal**: Fix performance issues (JSONB bloat, slow queries) before adding new features. Establish schema foundation for multi-content-type support.
**Depends on**: Phase 10.5 complete
**Requirements**: DBOPT-01 through DBOPT-07
**Success Criteria** (what must be TRUE):
  1. content.response JSONB trimmed to essential paths only (< 500 bytes avg vs current 2,469 bytes)
  2. 8 columns promoted from JSONB: view_count, like_count, comment_count, channel_title, published_at, tags, description, duration
  3. Composite indexes exist for all sort/filter combinations
  4. Server-side sort works for all ActivityTable columns
  5. Server-side filter works with ILIKE for text columns
  6. No GORM slow query warnings (all queries < 100ms)
  7. All existing tests pass after migration
**Estimated effort**: 3-4 weeks
**Risk**: LOW — optimization only, no new features

### Phase 12: Authentication & Security
**Goal**: Replace user dropdown selector with proper authentication. Secure all mutations. Enable user-specific features.
**Depends on**: Phase 11 (clean schema foundation)
**Requirements**: AUTH-01 through AUTH-13
**Success Criteria** (what must be TRUE):
  1. User can register with username/password (Argon2id hashed)
  2. User can log in and receive JWT access token (15 min expiry)
  3. Refresh token stored in httpOnly cookie (7 days)
  4. All GraphQL mutations require valid authentication
  5. Protected routes redirect unauthenticated users to /login
  6. TanStack Query cache scoped by user ID
  7. Logout clears tokens and cache (no data leakage)
  8. Login/Register pages render correctly on mobile
**Estimated effort**: 2-3 weeks
**Risk**: MEDIUM — security-critical, needs thorough testing

Plans:
- [ ] 12-01-PLAN.md — Backend: User password field, Argon2 hashing, JWT generation
- [ ] 12-02-PLAN.md — Backend: Chi middleware for JWT validation, context injection
- [ ] 12-03-PLAN.md — Backend: Login/Register GraphQL mutations
- [ ] 12-04-PLAN.md — Frontend: Auth state with Svelte 5 runes, token storage
- [ ] 12-05-PLAN.md — Frontend: Login/Register pages with form validation
- [ ] 12-06-PLAN.md — Frontend: Protected routes, automatic token refresh
- [ ] 12-07-PLAN.md — Frontend: TanStack Query cache scoping, logout handling
- [ ] 12-08-PLAN.md — Integration: End-to-end auth flow testing

### Phase 13: Content Categories
**Goal**: Enable content categorization with Google NL taxonomy. Add Claude-powered auto-suggestion.
**Depends on**: Phase 12 (auth for user-specific categories later)
**Requirements**: CAT-01 through CAT-08
**Success Criteria** (what must be TRUE):
  1. 20 content categories available (Google NL taxonomy subset)
  2. Category stored in lookup table with ltree support
  3. Category picker component in Add Video flow
  4. ActivityTable filterable by category column
  5. Category badge displayed in content row
  6. Claude API suggests category on new content (user confirms)
  7. Category statistics visible (count per category)
**Estimated effort**: 2-3 weeks
**Risk**: LOW — well-understood patterns

### Phase 14: AG Grid Power Features
**Goal**: Add toolbar with power-user controls for filter/column management. Persist user preferences.
**Depends on**: None (can parallel with other phases)
**Requirements**: GRID-01 through GRID-09
**Success Criteria** (what must be TRUE):
  1. Toolbar above ActivityTable with clear visual hierarchy
  2. "Clear all filters" button resets all column filters
  3. Column visibility picker shows/hides columns
  4. Multi-column sort works (Ctrl+click headers)
  5. Filter state persists in localStorage across sessions
  6. Column state persists in localStorage across sessions
  7. "Reset to defaults" restores original layout
  8. CSV export downloads visible data
  9. Keyboard shortcuts work (Ctrl+Shift+C = clear filters)
**Estimated effort**: 1-2 weeks
**Risk**: LOW — AG Grid Community APIs well-documented

### Phase 15: Discover Page
**Goal**: Enable YouTube search and category browsing to discover new content outside the library.
**Depends on**: Phase 13 (categories for browsing)
**Requirements**: DISC-01 through DISC-12
**Success Criteria** (what must be TRUE):

  2. Search input with 300ms debouncing

  4. Filters work: duration, upload date, sort order
  5. "Add to Library" button on each result
  6. Videos already in library visually indicated
  7. Category grid for browsing YouTube categories
  8. "Load More" pagination works
  9. Skeleton loading states during search
  10. YouTube API quota usage tracked/displayed
**Estimated effort**: 1-2 weeks
**Risk**: LOW — YouTube API well-understood, reuses existing patterns
