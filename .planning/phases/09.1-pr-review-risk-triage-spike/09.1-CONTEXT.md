# Phase 9.1: PR Review Risk Triage Spike — Context

**Gathered:** 2026-09-27
**Status:** Not started — spike, no blocking dependents

<domain>
## Phase Boundary

Research and prototype a way to classify PR diffs by review-worthiness before human review, so review attention scales with risk instead of diff size. Output is a decision on approach plus a working prototype, not a shipped feature.

</domain>

<decisions>
## Implementation Decisions (working hypothesis, to validate)

### Tier definitions

**Careful (needs human judgment):**
- Sequencing/ordering assumptions (webhook-before-row-exists races, goroutine ordering, cursor pagination before/after logic)
- State transitions and validation (GORM hooks, anything deciding whether a record can change)
- Non-additive migrations (ALTER COLUMN, DROP, type changes); additive ADD COLUMN with default is lower risk
- gqlgen resolvers with embedded business rules (vs pure pass-through)
- Auth/permission checks (Clerk integration points)
- Numeric/time comparisons where off-by-one or timezone errors are plausible

**Gray (skim, one-line summary, no auto-approve):**
- Svelte reactive statements ($:), where the dependency list is a logic decision
- Resolver -> service call swaps
- TanStack Query key / cache invalidation changes
- Config/env threading

**Skip-if-CI-passes:**
- gqlgen generated code (generated.go, models_gen.go)
- DI wiring in main.go
- chi route registration
- Renames, formatting, import reordering
- Lockfiles, patch/minor dependency bumps (major bumps -> gray)

### Key principle
The question is not diff size but: if this is wrong, does it fail loudly (CI catches it) or silently (only a human catches it)? The skip tier is only as trustworthy as what CI actually asserts, so audit test coverage first.

### Enforcement candidates (rank during spike)
1. Claude Code sub-agent/skill for classification + labeling, on existing subscription (no new cost)
2. PR-Agent (Apache 2.0) with require_risk_assessment / require_priority_files, routed through OpenRouter (openrouter/<model> prefix via LiteLLM) so classification runs on a cheap model and Claude is reserved for careful-tier deep review
3. Commercial tool with built-in risk tiers, only if 1-2 prove insufficient

</decisions>
