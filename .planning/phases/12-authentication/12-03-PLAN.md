<objective>
Implement Clerk webhook handler for user synchronization and on-demand user creation fallback.

Purpose: Keep the local users table in sync with Clerk's user directory. When users sign up, update their profile, or delete their account via Clerk, webhooks propagate those changes to the local database. An on-demand fallback handles the race condition where a user authenticates before their webhook fires.

Output: Working webhook endpoint that syncs Clerk user events to local DB, plus middleware-level on-demand user creation.
</objective>

  </files>
  <action>
    Create webhook_handler.go with:

    1. WebhookHandler struct:
       - webhookSecret string (CLERK_WEBHOOK_SIGNING_SECRET)
       - userRepo UserRepository

    2. ServeHTTP method:
       - Read raw body with io.ReadAll (MUST read before any parsing)
       - Verify Svix signature: svix.NewWebhook(secret).Verify(body, r.Header)
       - If verification fails: return 401
       - Parse event type and data
       - Switch on event type:
         - "user.created": Extract id, email, username from data → userRepo.CreateFromClerk
         - "user.updated": Extract id, email, username → userRepo.UpdateByClerkID
         - "user.deleted": Extract id → userRepo.DeactivateByClerkID
       - Return 200 OK

    3. Clerk webhook event data structure:
       ```go
       type ClerkWebhookEvent struct {
           Type string          `json:"type"`
           Data json.RawMessage `json:"data"`
       }

       type ClerkUserData struct {
           ID            string `json:"id"`
           Username      *string `json:"username"`
           EmailAddresses []struct {
               EmailAddress string `json:"email_address"`
           } `json:"email_addresses"`
           PrimaryEmailAddressID string `json:"primary_email_address_id"`
       }
       ```

    See 12-RESEARCH-go-backend.md Pattern 3 for reference.

    IMPORTANT: Read raw body FIRST, then verify signature, THEN unmarshal.
    If you reverse the order, Svix verification will always fail.
  </action>
