<objective>
Trim YouTube API JSONB response on ingest to reduce storage by 40-60% with no schema changes.

Purpose: The content.response JSONB column stores the full YouTube API response (~2,469 bytes/row, 93.7% of row data). Most of that data is never read by the application. Trimming to only essential paths reduces storage immediately without requiring any database migration.

Output: Modified YouTube client that trims response to essential paths before saving. New ingests are automatically trimmed. No migration needed — old data can be pruned on next update.
</objective>

1. Read `backend/internal/adapters/graphql/resolvers/helpers.go` to catalog all JSONB paths the application reads:

   - contentDetails: duration
   - id: videoId
   - Verify no other code paths read from response JSONB (grep the codebase)

2. Implement `trimResponse` function in `backend/internal/adapters/youtube/client.go`:
   - Accept `json.RawMessage` (full YouTube API response)
   - Unmarshal to intermediate struct containing only needed fields
   - Re-marshal to produce trimmed JSON
   - Retain: `items[0].id`, `items[0].snippet` (full), `items[0].statistics` (full), `items[0].contentDetails` (full)
   - Drop: `items[0].etag`, `items[0].kind`, `items[0].status`, `items[0].topicDetails`, `items[0].recordingDetails`, `items[0].player`, `items[0].liveStreamingDetails`, top-level `kind`, `etag`, `pageInfo`
   - Handle nil/empty input gracefully (return nil)

3. Wire `trimResponse` into the YouTube client's fetch flow:
   - After receiving YouTube API response and before storing in domain.Content
   - Call `content.Response = trimResponse(rawResponse)`

4. Write tests in `backend/internal/adapters/youtube/client_test.go`:
   - TestTrimResponse_RetainsEssentialPaths: verify snippet, statistics, contentDetails present
   - TestTrimResponse_DropsUnusedPaths: verify status, topicDetails, recordingDetails absent
   - TestTrimResponse_HandlesNilInput: verify nil input returns nil
   - TestTrimResponse_HandlesEmptyItems: verify empty items array handled
   - Use a realistic YouTube API response fixture (copy from existing test data or create minimal fixture)
