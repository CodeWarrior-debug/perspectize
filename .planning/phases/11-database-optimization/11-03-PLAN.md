<objective>
Update application layer to use extracted columns instead of JSONB path expressions for reading YouTube metadata.

Purpose: After Plan 02 adds extracted columns to the database, the application still reads from JSONB via helpers.go resolver code and uses JSONB path expressions in repository sort rules. This plan switches all reads to use the new columns, enabling index-backed sorting and eliminating JSONB extraction overhead on every query.

Output: Updated domain model, GraphQL resolver helpers, repository sort rules, and YouTube client that all use extracted columns. JSONB fallback for backward compatibility with un-backfilled rows.
</objective>

1. Update `backend/internal/core/domain/content.go`:
   - Add fields: `ChannelTitle *string`, `PublishedAt *time.Time`, `Description *string`, `Tags []string`, `ViewCount *int64`, `LikeCount *int64`, `CommentCount *int64`
   - These mirror the GORM model fields from Plan 02

2. Update domain ↔ GORM model mapping in repository:
   - In the toDomain/fromDomain converter functions, map all 7 new fields bidirectionally
   - Ensure Tags converts between `pq.StringArray` (GORM) and `[]string` (domain)

3. Update `backend/internal/adapters/graphql/resolvers/helpers.go`:
   - In `domainToModel` (or equivalent Content → GraphQL mapping function):
   - Replace JSONB extraction (`json.Unmarshal(content.Response, ...)`) with direct field access
   - For channelTitle: `m.ChannelTitle = content.ChannelTitle` (instead of parsing response JSON)
   - For viewCount: `m.ViewCount = content.ViewCount` (instead of parseInt from JSONB)
   - For all 7 fields: use extracted column value
   - Fallback: if extracted column is nil AND response is not nil, fall back to JSONB extraction (backward compat)

4. Update `backend/internal/adapters/repositories/postgres/helpers.go`:
   - Change sort rule SQLRepr from JSONB path expressions to column names:
     - `(response->'items'->0->'statistics'->>'viewCount')::BIGINT` → remove SQLRepr (use GORM field name `ViewCount`)
     - `(response->'items'->0->'statistics'->>'likeCount')::BIGINT` → remove SQLRepr
     - `response->'items'->0->'snippet'->>'publishedAt'` → remove SQLRepr
   - The gorm-cursor-paginator uses the GORM field name to generate SQL, so removing SQLRepr lets it use the column directly

5. Update `backend/internal/adapters/youtube/client.go`:
   - When creating domain.Content from YouTube API response, populate extracted fields:
     - `content.ChannelTitle = &item.Snippet.ChannelTitle`
     - `content.PublishedAt = parseTime(item.Snippet.PublishedAt)`
     - `content.Description = &item.Snippet.Description`
     - `content.Tags = item.Snippet.Tags`
     - `content.ViewCount = parseInt64(item.Statistics.ViewCount)`
     - `content.LikeCount = parseInt64(item.Statistics.LikeCount)`
     - `content.CommentCount = parseInt64(item.Statistics.CommentCount)`
   - Add helper functions `parseTime` and `parseInt64` if not already present

6. Run `go build ./...` and `go test ./...` in backend/ to verify
