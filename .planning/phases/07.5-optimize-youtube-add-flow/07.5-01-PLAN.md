<objective>
Eliminate redundant list refetch after adding a YouTube video by inserting the mutation response directly into the TanStack Query cache.

Purpose: After adding a video, the frontend currently re-fetches the entire paginated list (10-50 items). The mutation already returns the new item's data — use it to update the cache directly.
Output: Mutation selection set aligned with ContentItem, useAddVideo hook uses setQueriesData for instant cache insertion with background stale marking.
</objective>

    1. Add `ContentResponse` to the imports from content.ts:

    2. Replace the `onSuccess` handler. Current code:
    ```typescript
    onSuccess: (data: CreateContentResponse) => {
      const name = data?.createContentFromYouTube?.name ?? 'video';
      toast.success(`Added: ${name}`);
      queryClient.invalidateQueries({ queryKey: queryKeys.content.lists() });
    },
    ```

    New code:
    ```typescript
    onSuccess: (data: CreateContentResponse) => {
      const newItem = data.createContentFromYouTube;
      toast.success(`Added: ${newItem?.name ?? 'video'}`);

      // Insert new item at top of all active list caches
      queryClient.setQueriesData<ContentResponse>(
        { queryKey: queryKeys.content.lists() },
        (oldData) => {
          if (!oldData) return oldData;
          return {
            content: {
              ...oldData.content,
              items: [newItem, ...oldData.content.items],
              totalCount: (oldData.content.totalCount ?? 0) + 1,
            },
          };
        }
      );

      // Mark stale for eventual consistency (no immediate refetch)
      queryClient.invalidateQueries({
        queryKey: queryKeys.content.lists(),
        refetchType: 'none',
      });
    },
    ```

    Key changes:
    - `setQueriesData` updates ALL cached list queries matching the key prefix
    - New item prepended to `items` array (appears at top since default sort is updatedAt DESC)
    - `totalCount` incremented so pagination controls stay accurate
    - `invalidateQueries` with `refetchType: 'none'` marks as stale without triggering immediate refetch — next natural trigger (window focus, staleTime, navigation) will sync
  </action>
