# Plan 18-02: URL State Management & Grid State Utilities

## Goal

Create the URL ↔ component state synchronization layer for the Activity page. Build utilities to serialize/deserialize AG Grid filter models to URL params, and a reactive hook that keeps SvelteKit `$page.url.searchParams` in sync with grid state.

## Wave

Wave 1 (can run in parallel with Plan 18-01)

## Context

Currently, ActivityTable manages all state internally (`sortBy`, `sortOrder`, `filterText`, `currentPage`, `pageSize`, `cursors`). Nothing is reflected in the URL. The page-level search input (`searchText` in `+page.svelte`) is passed as a prop but never consumed.

This plan creates the infrastructure for URL-driven state. The actual wiring into ActivityTable happens in Plan 18-03.

## must_haves

```yaml
truths:
  - gridUrlState.ts utility module exists at frontend/src/lib/utils/gridUrlState.ts
  - parseGridParams() reads URLSearchParams and returns typed GridParams object with mode, sort, dir, page, pageSize, q, and filter map
  - serializeGridParams() converts GridParams to URLSearchParams string (omitting defaults)
  - filterToUrlParams() converts AG Grid FilterModel to f.* URL params
  - urlParamsToFilter() converts f.* URL params back to AG Grid FilterModel
  - urlParamsToGraphQLFilter() converts f.* URL params to GraphQL ContentFilter input
  - Range syntax supported: "1000.." (min only), "..5000" (max only), "1000..5000" (both)
  - All utilities have unit tests with 80%+ coverage
  - Frontend tests pass (pnpm run test:run in frontend/)
```

### Task 1: Create GridParams Type and URL Serialization

**File:** `frontend/src/lib/utils/gridUrlState.ts`

Define the core types and serialization functions:

```typescript
/** Data mode: 'all' = server-side, 'loaded' = client-side */
export type DataMode = 'all' | 'loaded';

/** Parsed grid state from URL params */
export interface GridParams {
  mode: DataMode;
  sort: string;        // AG Grid colId (e.g., 'views', 'updatedAt')
  dir: 'asc' | 'desc';
  page: number;        // 1-indexed
  pageSize: number;
  q: string;           // Text search
  filters: Record<string, string>; // f.type=youtube, f.views=1000..5000, etc.
}

/** Default values — omitted from URL when matching */
export const GRID_DEFAULTS: GridParams = {
  mode: 'loaded',
  sort: 'updatedAt',
  dir: 'desc',
  page: 1,
  pageSize: 10,
  q: '',
  filters: {},
};

/** Parse URLSearchParams into GridParams */
export function parseGridParams(params: URLSearchParams): GridParams { ... }

/** Serialize GridParams to URL search string (omitting defaults) */
export function serializeGridParams(state: GridParams): string { ... }
```

Key behaviors:
- `parseGridParams` handles missing params by falling back to `GRID_DEFAULTS`
- `serializeGridParams` omits params that match defaults (clean URLs)
- `page` is 1-indexed in URL, stored as 1-indexed in GridParams
- Filters use `f.` prefix: `f.type=youtube`, `f.views=1000..`, `f.date=2024-01..2024-06`

**Range syntax for number/date filters:**
- `1000..` → min only (AG Grid: `greaterThan` or `greaterThanOrEqual`)
- `..5000` → max only (AG Grid: `lessThan` or `lessThanOrEqual`)
- `1000..5000` → both (AG Grid: `inRange`)

**Column → URL param mapping:**

| AG Grid colId | URL param | Type | Example |
|---------------|-----------|------|---------|
| type | `f.type` | text | `youtube` |
| duration | `f.duration` | range (seconds) | `60..600` |
| views | `f.views` | range | `1000..` |
| likes | `f.likes` | range | `..5000` |
| publishDate | `f.date` | date range (ISO) | `2024-01..2024-06` |
| channel | `f.channel` | text | `mkbhd` |
| tags | `f.tags` | text | `cooking` |
| description | `f.desc` | text | `tutorial` |
| createdAt | `f.added` | date range | `2024-01..` |
| updatedAt | `f.updated` | date range | `..2024-12` |

**GraphQL ContentFilter mapping:**
- `f.type=youtube` → `{ contentType: "YOUTUBE" }`
- `f.views=1000..5000` → `{ minViewCount: 1000, maxViewCount: 5000 }`
- `f.duration=60..600` → `{ minLengthSeconds: 60, maxLengthSeconds: 600 }`
- `f.date=2024-01..2024-06` → `{ publishedAfter: "2024-01", publishedBefore: "2024-06" }`
- `f.channel=mkbhd` → `{ channelTitle: "mkbhd" }`
- `f.tags=cooking` → `{ tagContains: "cooking" }`
- `f.desc=tutorial` → `{ descriptionSearch: "tutorial" }`
- `q=cooking` → `{ search: "cooking" }`

## Risks

- **AG Grid filter model structure**: Filter model shape varies by filter type (text/number/date) and by condition count (single vs combined). Handle the common single-condition cases; combined conditions can be added later.
- **Date format inconsistency**: AG Grid uses `YYYY-MM-DD` format, URL params may use shorter `YYYY-MM`. Need clear parsing rules.
