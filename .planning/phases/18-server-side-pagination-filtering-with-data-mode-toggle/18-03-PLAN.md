# Plan 18-03: Data Mode Toggle UI & Grid Integration

## Goal

Wire everything together: add the data mode toggle to ActivityTable, route AG Grid events through server-side or client-side paths based on mode, connect URL state to TanStack Query, and update the Activity page to use URL-driven state.

## Wave

Wave 2 (depends on Plan 18-01 and Plan 18-02)

## Context

After Plans 01 and 02:
- Backend supports expanded filtering/sorting on all columns
- `gridUrlState.ts` provides URL ↔ state serialization
- ActivityTable still uses internal state management with hybrid server/client approach

This plan integrates both layers and adds the toggle UI.

```yaml

  - "Loaded X Items" shows dynamic count of loaded rows and has hover tooltip explaining mode
```

### Task 2: Refactor ActivityTable State to URL-Driven

**File:** `frontend/src/lib/components/ActivityTable.svelte`

Major refactor of state management:

1. **Remove internal state** for sort/filter/page/pageSize — derive everything from URL params. **Delete the local `SORT_FIELD_MAP` constant** (lines 27-37 of current ActivityTable.svelte) — replaced by `COL_TO_SORT` from `gridUrlState.ts`.

2. **Add URL sync effect**: Read from `$page.url.searchParams` on mount and on URL changes:

   ```typescript
   import { page } from '$app/state';
   import { goto } from '$app/navigation';
   import { parseGridParams, serializeGridParams, COL_TO_SORT, urlParamsToGraphQLFilter } from '$lib/utils/gridUrlState';
   import type { DataMode, GridParams } from '$lib/utils/gridUrlState';

   // Derive grid params from current URL
   const gridParams = $derived(parseGridParams(page.url.searchParams));

   // Derived state from URL
   const mode = $derived(gridParams.mode);
   const sortBy = $derived(COL_TO_SORT[gridParams.sort] ?? 'UPDATED_AT');
   const sortOrder = $derived(gridParams.dir === 'asc' ? 'ASC' : 'DESC');
   const pageNum = $derived(gridParams.page); // 1-indexed
   const pageSize = $derived(gridParams.pageSize);
   const searchText = $derived(gridParams.q);
   const filters = $derived(gridParams.filters);
   ```

3. **URL update helper**:
   ```typescript
   function updateUrl(changes: Partial<GridParams>, replace = true) {
     const updated = { ...gridParams, ...changes };
     const search = serializeGridParams(updated);
     const url = search ? `?${search}` : page.url.pathname;
     goto(url, { replaceState: replace, keepFocus: true, noScroll: true });
   }
   ```

4. **Conditional data fetching based on mode**:

   ```typescript
   // Server-side mode: build GraphQL filter from URL params
   const graphqlFilter = $derived(
     mode === 'all'
       ? urlParamsToGraphQLFilter(filters, searchText)
       : searchText ? { search: searchText } : undefined
   );

   // Cursor management for page numbers
   let cursors = $state<(string | null)[]>([null]);
   const currentCursor = $derived(cursors[pageNum - 1] ?? null); // 1-indexed page → 0-indexed cursor array

   const contentQuery = createQuery(() => ({
     queryKey: queryKeys.content.list({
       sortBy: mode === 'all' ? sortBy : 'UPDATED_AT',
       sortOrder: mode === 'all' ? sortOrder : 'DESC',
       search: mode === 'all' ? searchText : '',
       first: pageSize,
       after: currentCursor,
       filter: mode === 'all' ? graphqlFilter : undefined,
     }),
     queryFn: async () => {
       const response = await graphqlClient.request<ContentResponse>(LIST_CONTENT, {
         first: mode === 'all' ? pageSize : 100, // Load more in client mode for filtering
         after: mode === 'all' ? currentCursor : null,
         sortBy: mode === 'all' ? sortBy : 'UPDATED_AT',
         sortOrder: mode === 'all' ? sortOrder : 'DESC',
         filter: graphqlFilter,
         includeTotalCount: true,
       });

       // Update cursors for page navigation
       if (response.content.pageInfo.hasNextPage && response.content.pageInfo.endCursor) {
         if (cursors.length === pageNum) {
           cursors = [...cursors, response.content.pageInfo.endCursor];
         }
       }

       return response;
     },
     placeholderData: keepPreviousData,
     staleTime: 60 * 1000,
   }));
   ```

5. **Mode-conditional AG Grid event handlers**:

   ```typescript
   onSortChanged: (event: SortChangedEvent) => {
     if (mode === 'loaded') return; // AG Grid handles client-side sort
     // Server-side: update URL → triggers refetch
     const sortModel = event.api.getColumnState()...;
     if (sortModel.length > 0) {
       updateUrl({ sort: sortModel[0].colId, dir: sortModel[0].sort, page: 1 });
       cursors = [null]; // Reset cursor stack
     }
   },

   onFilterChanged: (event: FilterChangedEvent) => {
     if (mode === 'loaded') return; // AG Grid handles client-side filter
     // Server-side: debounce → convert filter model → update URL
     clearTimeout(debounceTimer);
     debounceTimer = setTimeout(() => {
       const filterModel = event.api.getFilterModel();
       const urlFilters = filterToUrlParams(filterModel);
       updateUrl({ filters: urlFilters, page: 1 });
       cursors = [null];
     }, 500);
   },
   ```

6. **Prevent AG Grid from client-side re-sorting in "All Items" mode**:
   The grid stays in `ClientSideRowModelModule` always. In "All Items" mode, data arrives pre-sorted from the server. To prevent AG Grid from client-side re-sorting the already-sorted data, use the `postSortRows` callback:

   ```typescript
   // In gridOptions:
   postSortRows: (params) => {
     // In "All Items" mode, data is server-sorted — don't re-sort client-side
     if (mode === 'all') return;
     // In "Loaded" mode, let AG Grid sort normally (default behavior)
   },
   ```

   Additionally, when mode changes to 'all', reset AG Grid's internal sort model to match URL state without triggering a client-side re-sort:

   ```typescript
   $effect(() => {
     if (!gridApi || !gridReady || mode !== 'all') return;
     // Sync sort indicators to URL state without triggering onSortChanged
     skipNextSortEvent = true;
     gridApi.applyColumnState({
       state: [{ colId: gridParams.sort, sort: gridParams.dir }],
       defaultState: { sort: null },
     });
   });
   ```

   The `skipNextSortEvent` flag prevents the `onSortChanged` handler from re-updating the URL when we're just syncing visual indicators.

   AG Grid column sort headers remain clickable — they trigger `onSortChanged` which routes to the URL → server refetch path. The `postSortRows` callback ensures AG Grid doesn't re-sort the server-sorted data after it arrives.

2. **Wire search input to URL params**:

   ```svelte
   <script lang="ts">
     import { page } from '$app/state';
     import { goto } from '$app/navigation';
     import { parseGridParams, serializeGridParams } from '$lib/utils/gridUrlState';

     const gridParams = $derived(parseGridParams(page.url.searchParams));

     let searchInput = $state(gridParams.q);

     // Debounced search → URL update
     let searchTimer: ReturnType<typeof setTimeout>;
     function handleSearchInput(value: string) {
       searchInput = value;
       clearTimeout(searchTimer);
       searchTimer = setTimeout(() => {
         const updated = { ...gridParams, q: value, page: 1 };
         const search = serializeGridParams(updated);
         goto(search ? `?${search}` : '/', { replaceState: true, keepFocus: true, noScroll: true });
       }, 300);
     }
   </script>

   <Input
     type="text"
     placeholder="Search content..."
     value={searchInput}
     oninput={(e) => handleSearchInput(e.currentTarget.value)}
     class="pl-9"
   />
   ```

## Risks

- **AG Grid sort state sync**: Setting AG Grid column state from URL on mount may conflict with the `onSortChanged` handler (infinite loop). Mitigation: use a `skipNextSortEvent` flag to break the loop.
- **Cursor invalidation on mode switch**: Switching from "All Items" (page 3 with server cursor) to "Loaded" mode invalidates cursors. Mitigation: reset cursor stack on mode switch.
- **Large data in "Loaded" mode**: `first: 100` loads 100 items for client-side filtering. If dataset grows, may need to increase or add a "load all" option. Acceptable for MVP.
